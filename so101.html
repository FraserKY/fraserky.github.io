Imitation learning on an SO-101 arm

This page details my journey into imitation learning and ACT. I wanted to learn more about how these systems worked, so I printed and built a pair of SO-101 robot arms, recorded demonstrations of a pick-and-place task, trained an ACT policy on them, and got the robot arm to complete the task autonomously.

This is the write-up. It includes the things that didn’t work, because those took most of the time.

Task

Placing a cube into a box

My aims were to learn about a new technology, and I wanted to start small and my first task was to teach the robot arm to pick up a green cube and put it in a box.

The trained policy running autonomously on local CPU inference, at both loop rates.

The hardware setup is a pair of SO-101 arms. One has a ‘gripper’ on the end (a follower), and the other a handle (a leader). I printed the parts for both and assembled them myself. To record a demonstration I move the leader by hand and the follower copies it, while two cameras (one on the follower’s wrist, one overhead) record what it sees along with its joint positions.

The overhead camera used to sit on a stand in front of the follower arm. After getting poor performance from the first set of data and training, I decided an overhead view would produce a more varied output, resulting in a better trained model and inference performance. Moving it meant re-recording the dataset. I also placed some visual markers to ensure everything could be placed in the same position, to make the task more deterministic, in an attempt to get better results.

Status

It works inside the conditions it was trained on

The policy picks up the cube and puts it in the box reliably, as long as the cube, the box and the cameras are where they were during the demonstrations. Local CPU inference runs at about 2.5 Hz so the motion is jerky, but it still finishes the task, which makes me think the model itself is okay, but the rate of inference is likely a problem.

My next challenge is to get the robot to pick up a randomly placed cube and put it in the box. This is known as generalisation: getting the robot to perform the task despite changes in its environment.

I recorded a second 50 episode dataset with the cube placed randomly and trained on it for 20k steps, but that policy performed badly.

From some research online, I think it’s likely that 50 episodes is too few to achieve generalisation, and I’ll need to collect more data.

My next step is to collect more training data with the cube, placed deliberately in a number of discrete locations, and then retrain the model.
